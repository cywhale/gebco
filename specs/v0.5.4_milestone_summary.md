## 3. Algorithm Changes

### v0.5.3 hardening changes

Key runtime/contract safety changes:

* `jsonsrc` now goes through a 7-layer defense path in [src/jsonsrc.py](/Users/cywhale/proj/gebco/src/jsonsrc.py)
* lon/lat validation centralized in [src/validation.py](/Users/cywhale/proj/gebco/src/validation.py)
* mode parsing centralized in [src/modes.py](/Users/cywhale/proj/gebco/src/modes.py)
* structured request logging added in [src/logger.py](/Users/cywhale/proj/gebco/src/logger.py)
* bbox caps enforced instead of letting pathological requests run to OOM

### v0.5.4 line/polyline redesign

Old issue:

* repeated `np.append(...)` in hot loops caused O(n²)-like growth behavior on long / sparse line walks

Delivered changes:

* Python list accumulation + one terminal `np.asarray(...)`
* `np.absolute(scalar)` replaced by builtin `abs(scalar)` in hot scalar paths
* geodesic distance path switched from `geopy` to `pyproj.Geod.inv`

Files:

* [src/zprofile.py](/Users/cywhale/proj/gebco/src/zprofile.py)
* [src/xmeridian.py](/Users/cywhale/proj/gebco/src/xmeridian.py)

### v0.5.4 polygon redesign

Old issue:

* polygon cost scaled with the entire bbox, not with returned rows
* `meshgrid + shapely.points + shapely.contains` caused large CPU and RSS spikes
* sparse / ribbon / cross-180 polygons were pathological even when output rows were modest

Delivered changes:

* cell-budget batching via `GEBCO_POLYGON_BATCH_CELLS`
* `shapely.contains_xy(...)` instead of `shapely.points + shapely.contains`
* `gc.collect()` after each batch
* `shapely.prepare(...)` once per polygon half before containment checks
* removal of hot-path debug `print(...)`

File:

* [src/polyhandler.py](/Users/cywhale/proj/gebco/src/polyhandler.py)

## 5. Final Runtime Defaults

Final defaults after v0.5.4:

* `GEBCO_MAX_BBOX_CELLS_LINE = 2e8`
* `GEBCO_MAX_POLYGON_CELLS = 5e7`
* `GEBCO_POLYGON_BATCH_CELLS = 1_000_000`
* `GEBCO_DASK_POOL_SIZE = 4`

Rationale for the polygon cap change:

* v0.5.3 kept `2e9` as a provisional guard because the old polygon algorithm was too weak to justify a real cap
* v0.5.4 reduced actual polygon cost enough that `5e7` is now a real, defensible default

## 6. Breaking / Milestone Significance

These two versions should be treated as milestone-level changes.

### Why v0.5.3 is milestone-level

* request-surface hardening
* validation normalization
* structured logging
* explicit bbox guards
* new test tree and verification discipline

### Why v0.5.4 is milestone-level

* real algorithm redesign, not just tuning
* line/polyline hot-loop rewrite
* polygon path redesign with measured wall/RSS wins
* final tightening of polygon safety default

### Compatibility note

The public API contract is still broadly compatible, but these releases
change important operational semantics:

* oversized requests are rejected more explicitly
* remote `jsonsrc` handling is more defensive
* polygon performance and resource behavior are materially different
* deployment/runtime defaults are stronger than in v0.5.2

## 7. Remaining Known Issues

Still open, but not blockers for this milestone:

* `xmeridian.py` still emits divide-by-zero `RuntimeWarning` in some tests
  when slope is degenerate; tests pass, but this could be cleaned up later
* further Zarr-aware sparse-read optimisation is still possible after H9
* `GEBCO_DASK_POOL_SIZE` default remains `4`; no default-off migration yet
